# ARGB Studio 🎨 — باندل مستقل RGB

برنامه‌ی شخصی برای کنترل نور ARGB کل سیستم (کیس، فن‌ها، فن CPU و نور مادربرد) — **همه‌چیز توی یک پوشه، بدون نصب جداگانه‌ی هیچ برنامه‌ای.**

## ⬇️ دانلود آماده اجرا

**[آخرین نسخه (zip پرتابل)](https://github.com/sharkgitHB/ARGB-Studio/releases/latest)** — همه‌چیز داخلشه (برنامه + لایه سخت‌افزار + پایتون داخلی). Extract کن → دابل‌کلیک `run.bat` → تمام.

این ریپو فقط سورس است؛ باندل کامل و آماده‌ی اجرا در **Releases** منتشر می‌شود.

```
argb-studio/
├── run.bat              ← اجرا (دابل‌کلیک) — خودش دسترسی ادمین می‌گیره
├── main.py              ← نقطه شروع برنامه
├── app/                 ← رابط گرافیکی + موتور افکت + اتصال
├── runtime/openrgb/     ← لایه سخت‌افزار (OpenRGB پرتابل — مخفی و هدلس اجرا میشه)
└── runtime/openrgb-config/  ← تنظیمات سخت‌افزار (اینجا ذخیره میشه، به APPDATA دست نمی‌زنه)
```

## نحوه کار (خلاصه)

برنامه موقع باز شدن، OpenRGB باندل‌شده رو **بدون هیچ پنجره‌ای** اجرا می‌کنه، به سرور SDK وصل میشه و رنگ‌ها رو با نرخ ۳۰fps می‌فرسته. با بستن برنامه، اون لایه هم بسته میشه. چیزی که تو می‌بینی فقط پنجره‌ی خود برنامه‌ست.

## اجرا

**دابل‌کلیک روی `run.bat`** — پنجره UAC باز شد Yes بزن (برای دسترسی به مادربرده). دفعه اول محیط پایتون رو خودش می‌سازه.

- تیک «**شروع خودکار با ویندوز**» داخل برنامه = موقع روشن شدن سیستم خودش بالا میاد (بدون پاپ‌آپ UAC، با دسترسی کامل).
- اجرای برنامه دوباره خطا نمیده — نسخه دوم فقط پیام «برنامه باز است» میده.

## استفاده — فقط بار اول

1. روی هر زون (مثلاً «Addressable RGB Header 1» که هاب فن‌هات بهش وصله) کلیک کن.
2. **«تعداد نور (LED)»** رو با مجموع نورهای وصل‌شده به اون هدر تنظیم کن و «ثبت» بزن.
   - مثال: ۳ فن × ۸ LED = ۲۴. اگه مطمئن نیستی، یه عدد بزن و ببین چند تا فن روشن میشه؛ بعد دقیقش کن.
3. همین عدد در تنظیمات ذخیره میشه و دفعات بعد لازم نیست دوباره بزنی.
4. افکت، رنگ، سرعت و روشنایی رو انتخاب کن — یا «اعمال به همه بخش‌ها» رو بزن.

> نور مادربرد (لوگوی TUF) بدون تنظیم تعداد کار می‌کنه. فن‌های هاب روی یکی از سه هدر ARGB هستن — کدوم هدر رو با امتحان تعداد نور پیدا می‌کنی.

## تست و اشکال‌زدایی

```bat
.venv\Scripts\python main.py --check      :: تست عمومی + لیست دستگاه‌ها
.venv\Scripts\python tests\e2e.py         :: تست کامل بدون UI (اجرای لایه سخت‌افزار)
```

| مشکل | راه‌حل |
|---|---|
| «OpenRGB یافت نشد» | پوشه `runtime/openrgb` کنار برنامه باشه |
| هدر توی لیست نیست یا نور تغییر نمی‌کنه | برنامه رو از `run.bat` اجرا کن (با ادمین)، نه مستقیم با پایتون |
| برنامه باز نمیشه و میگه «باز است» | یه نسخه از قبل در حال اجراست (شاید در Task Manager دنبال ARGB بگرد) |
| فن‌ها فقط تعداد کمی از LEDها رو روشن کردن | عدد «تعداد نور» رو بیشتر کن |

## فنی

- افکت‌ها: رنگین‌کمان / نفس‌کشان / موج / ثابت / خاموش — همه با ۳۰fps و رنگ per-LED
- همه ارسال‌ها روی thread جدا انجام میشه؛ UI هیچ‌وقت فریز نمیشه
- اگه سرور وسط کار بیفته، برنامه خودش متوجه میشه و دکمه «اتصال مجدد» دوباره بالا میاره
- تنظیمات افکت‌ها در `last_state.json` ذخیره و دفعات بعد بازگردانی میشه
- OpenRGB با `--server --config runtime/openrgb-config` اجرا میشه؛ یعنی هم هدلسه هم تنظیماتش (مثل تعداد LED هدرها) داخل همین پوشه ذخیره میشه

## بستن بسته برای دوستان 📦

کل پوشه مستقل از برند مادربرده — هر قطعه‌ای که لایه سخت‌افزار (OpenRGB) بشناسد
(ASUS / MSI / Gigabyte / ASRock و کنترلرهای USB معروف) خودکار در برنامه ظاهر می‌شود.
پایتون هم داخل بسته‌ست؛ روی سیستم مقصد **هیچ پیش‌نیازی لازم نیست**.

ساخت بسته:
```bat
.venv\Scripts\python scripts\package.py     →  ..\dist\ARGB-Studio-Portable.zip
```

راهنمای دوستت (سه قدم):
1. پوشه را از حالت zip خارج کن — **جایی غیر از Program Files** (مثلاً دسکتاپ یا D:\)
2. دابل‌کلیک `run.bat` → در پنجره UAC بزن **Yes** (احتمالاً SmartScreen هم "More info → Run anyway" می‌خواهد)
3. داخل برنامه دکمه **«راه‌اندازی اولیه (پیدا کردن فن‌ها)»** — هر هدر تنظیم‌نشده نارنجی چشمک می‌زند؛ اگر نوری که نارنجی شده به فن‌هایش وصله «بله» بزن. همین!

> جزئیات حقوقی اجزای باندل‌شده (OpenRGB/GPL، فونت وزیرمتن، پایتون) در `THIRD-PARTY-NOTICE.md` آمده است.
